WorkBuddy 简介
WorkBuddy 是 7×24 云端 AI 智能助理平台，能够听懂用户意图、进行规划思考并调度工具完成执行，可在手机、PC、浏览器、小程序、智能硬件等多端被调用，为用户提供一致的 AI 体验与跨端记忆。

智能规划执行

本地环境操作

多智能体协同
多个子智能体并行分工、结果聚合，一人即拥有一个 AI 团队。
跨端遥控
手机、硬件、Web 唤起同一 thread，任务与产物在多端无缝续接。
定时与主动服务
7×24 定时任务，实现盯盘、日程、舆情、内容生产等主动能力。
生态扩展
7 万余 Skills、Connector 与 MCP 组件即插即用，能力随生态持续演进。

2
硬件接入的价值
AI 行业的竞争阶段正在从"谁的模型强"转向"谁先进入真实场景"。在两百亿量级的智能设备成为新一代信息入口的过程中，硬件为 WorkBuddy 提供了眼睛、耳朵与执行末端，WorkBuddy 为硬件补上了云端大脑与决策能力。
2.1 Agent 价值的三重放大
触点密度
硬件的存在提高了 AI 被触达的频率与场景覆盖，使 AI 从"打开使用"变成"随身待命"。
上下文深度
硬件的传感器能提供位置、时间、语音、画面等现场上下文，使 AI 的判断建立在真实世界之上。
执行半径
硬件的显示、播报、录制与联动能力，让 AI 的决策能够落到物理世界，不再停留在屏幕之内。
2.2 硬件三痛点与解法
同质化严重
硬件参数持续拉满，缺少 AI 灵魂与差异化卖点，产品难以形成溢价。
注入 AI 灵魂
自研 Agent 内核开箱即用，用户体验立刻拉开层次。
AI 沦为摆设
功能堆叠但缺乏日常调用理由，用户使用频率低、粘性弱。
主动服务
定时任务与跨端记忆把 AI 变成高频刚需，日活与调用同步提升。
自建 AI 成本高
组建 AI 团队、追赶模型迭代的周期长、投入大、跟不上节奏。
标准 SDK 与 API
快速接入、零 AI 团队即可上线，随 WorkBuddy 同频升级。

4.3 四种模式详解
怎么选：
从已回收的伙伴意向看，近七成伙伴以「双向打通」起步——接入轻、双方各有入口、可快速验证效果；「硬件预装」适合有海量设备的大厂，通常涉及 WorkBuddy 侧付费或分成投入，门槛与周期相对较高。实践中两种组合最常见：
双向打通 + 能力集成/品牌专区
、
双向打通 + 硬件连接
，可同时推进、分阶段落地。
1
硬件预装
谁适合
有海量存量设备/用户、有系统级或应用商店分发入口的 PC / 平板 / 终端大厂
怎么做
WB 预装到伙伴设备 + 应用市场分发；无自有算力 → WB 提供产品（可按行业场景做定制版）、厂商集采会员；有自有算力 → 算力分成或 license 结算
代表方向
PC / 平板品牌预装合作、云桌面预装、传统终端定制
说明
该模式涉及角色较多，决策周期长；建议设备体量有限的团队优先从模式②起步验证
2
双向打通（OpenAPI 双向调用）
主推
谁适合
有自有 App、希望与 WB 双向能力互通、共同放大用户体验的伙伴
怎么做（两条同步推进，共同构成"双向打通"）
① 伙伴 App 调 WB
——伙伴通过 WorkBuddy Task OpenAPI 接入自有 App，用户在
伙伴 App 里调用 WB 能力
② 用户在 WB 内使用伙伴 App 信息资产
——伙伴 App 通过自家 OpenAPI 向 WB 开放，用户可在
WB 里访问和使用其在伙伴 App 中的信息资产
💡 主推形态是两条都要做——两侧入口都能触达对方能力，用户体验和商业价值最大化。
3
硬件连接到 WB
谁适合
具备 WiFi / 蓝牙能力的设备厂商，希望硬件连接到 WB，用户在 WB 上完成设备使用与管理
怎么做
硬件主要通过 WB 给用户交付软件服务，绑定到 WB 账侧，成为可调度物理节点。
只和行业内头部重点伙伴合作。
代表方向
键盘、鼠标、耳机等
4
能力集成 + 品牌专区
谁适合
有软件能力 / 内容 / 服务的 SaaS、工具、内容伙伴，希望以更轻的方式融入 WB 生态并建立品牌入口
怎么做
能力集成（三种技术形态任选或组合）
：
Skill
：伙伴写好的 agent skill 挂进 WB
Connector
：伙伴数据/能力做成 connector（形态类似现有的飞书、TAPD、企业微信连接器）
专家
：伙伴以"专家"或"专家团"身份入驻 WB 专家中心
品牌专区
：可为伙伴配置独立的品牌落地页 / 专区，承载伙伴自有的一批专家 + skill + connector 组合，作为品牌方在 WB 内的独立入口。
代表方向
SaaS / 工具 / 内容伙伴
4.4 合作范本
下列范本以品牌方视角描述一次合作从"识别自己"到"看见样子"的完整路径。
（以下商务结构为框架性参考，具体金额与结算周期以双方协议为准。）
范本 A · 双向打通（模式②）
合作方画像
：有自有 App 的智能设备品牌，希望用户在自家 App 里调用 WB 能力，同时让 WB 用户也能访问其 App 内的信息资产。
合作形态
：伙伴通过 Task OpenAPI 接入 WB 能力到自有 App；同时通过自家 OpenAPI 向 WB 开放数据能力。
产品长这样
：用户在伙伴 App 里直接用 WB AI 完成任务 → 同时在 WB 里也能查看和操作伙伴 App 的信息资产。
商务结构
：会员/积分采购 + 算力用量结算。
范本 B · 外设接入 WB（模式③）
合作方画像
：键盘、鼠标、耳机等外设厂商，具备蓝牙/WiFi 能力，希望设备成为 WB 生态的物理外延。
合作形态
：厂商提供 Claw / Connector 能力，用户在 WB 内联动硬件；支持蓝牙轻量化接入。
产品长这样
：用户在 WB 里直接操控外设（语音输入/快捷调用/状态查询）→ 硬件状态与 WB 账号绑定。
商务结构
：品牌授权 + 算力分成 + 联合投放。
4.5 商业模式与结算
开放生态：
WorkBuddy 对硬件伙伴开放自助接入——伙伴可通过开放平台（open.workbuddy.cn）自助申请并完成接入（目前已有多家伙伴接入成功），接入环节目前不收费；完成接入的企业即可对外说明「适配 WorkBuddy」「兼容 WorkBuddy」。
基本原则：
硬件方卖硬件、WorkBuddy 卖 AI 能力，各自独立结算。针对不同类型的硬件方，WorkBuddy 开放以下三种商业路径，可单选或组合。
三种可开放的商业路径
个人会员 / 积分采购
：硬件方预付采购 WorkBuddy 会员额度或积分，随硬件赠送 / 兑换给最终用户，按采购规模阶梯定价。
会员 / 积分仅限赠送给最终用户，不可转售、不可对外售卖
算力 / 能力分成
：硬件设备侧调用 WorkBuddy Agent 能力，按 Task 用量 / API 调用量 / 订阅席位分成
品牌授权费
：适用于「WorkBuddy 认证」标识授权、战略集成、定制专区，一次性授权费或年度授权费
结算基本口径
会员 / 积分采购为预付费模式，采购需卷入商务对接，企业需具备腾讯云 UIN
权益发放必须通过 API 直充至最终用户账号，不允许直接向用户发放兑换码
用户身份基于 OAuth 授权后颁发的 open_id 唯一标识
合作数据每月对账，看板实时可查
（详见 §13.2）
具体阶梯价、分成比例、授权费通过商务窗口一事一议
商业化分级、二次付费规则与数据分账说明，以开放平台官网公示及双方商务协议为准
合作分层（L1 / L2）
L1 接入级
：开放平台自助申请、完成接入即达，目前不收费；可对外使用「适配 WorkBuddy」「兼容 WorkBuddy」文字表述（不加 Logo、不做认证标识）
L2 认证级
：需通过 WorkBuddy 官方认证标准，通过后可在产品与包装上使用「WorkBuddy 认证」标识，并签署品牌授权合同
如需联合 PR，或在产品上打 Logo 等品牌合作，请联系商务进一步沟通
品牌标识与对外表述细则详见 §12.5
合作边界
硬件售卖
：硬件的定价、渠道与销售由合作方自主运营，WorkBuddy 不干涉、不参与
软件保障
：软件相关部分（账号、权益、能力稳定性）由 WorkBuddy 做好保障
联合 PR / 市场宣推
：开放，需双方评估后执行

5.1 Agent 架构总览
WorkBuddy 的核心是一个云端 Agent 引擎，遵循「理解 → 规划 → 记忆 → 执行 → 调度」五层结构，硬件伙伴只需通过标准 API 调用整个引擎，不必自研任何一层。
理解
多模态输入解析：文本 / 语音 / 图像 / 屏幕，结合硬件上下文识别意图。
规划
目标拆解为多步任务，自主选择工具链与执行顺序。
记忆
跨端长期记忆 + 会话短期记忆，Thread 在多端连续续接。
执行
调用 Skills / Connector / MCP 完成实际动作，产出可交付物。
调度
7×24 定时任务、事件触发、多智能体协同分工。

11
常见问题
如何判断适合的合作模式？
参照第 4 章的三个问题：谁进谁、品牌与入口归属、用户与数据归属，答完即可归入四种模式之一。
个人票据有效期是多久？
由响应字段
expires_in
指定，默认 7200 秒。过期后使用
refresh_token
换新票，用户主动撤销后立即失效。
如何在合作方侧隔离多用户数据？
使用响应中的
openid
作为用户维度的存储与查询主键，同一
openid
对应的所有 WorkBuddy 资产（助理、任务）归属该用户。
本机（Local）类型的助理是否需要激活？
不需要。
allocate
（激活接口）仅适用于云端（cloud）助理。本机（local）助理依赖用户本机 WorkBuddy 客户端在线运行。
接口返回 401 应如何处理？
先尝试通过
refresh_token
续期。仍然返回 401 说明用户已撤销授权或权限发生变化，应引导用户重新完成 OAuth 授权。
硬件端能否直接调用 WorkBuddy API？
不建议。个人票据应保存在合作方后端，硬件通过合作方后端反向代理调用 API，以避免凭据泄露与合规风险。
本机能力的边界在哪里？
任务执行以云端为主；本机能力需用户 PC 安装 WorkBuddy 桌面客户端（当前覆盖 Mac 与 Windows），可读取本机文件、运行本机任务。手机等移动设备暂不支持本机执行，以云端任务与轻量交互为主。
MCP / Connector 接入的数据安全如何保障？
按权限范围（scope）逐项最小授权，票据由合作方后端保管，用户可随时撤销授权；合作方数据仅在用户授权的任务上下文中被调用，具体使用边界以授权协议与隐私政策为准。
支持哪些操作系统与平台？
桌面客户端当前覆盖 Mac 与 Windows；Linux（含 Ubuntu）桌面版暂未覆盖，有需求的伙伴可在开放平台官网登记，平台按需求量评估排期。
推广与分佣机制是怎样的？
合作涉及的推广、分佣与积分体现方式随商务协议约定，在开放平台提交合作意向后由商务团队一对一对接。

合作落地流程
WorkBuddy 与硬件伙伴的落地分两条路径：
自助接入
是默认路径，大多数伙伴可自行确认场景、按开放平台文档自助完成接入；
商务协作
面向希望深度合作、或现有文档与自身场景不匹配的伙伴，由商务一对一跟进。
12.1 两条接入路径
路径 A · 自助接入（默认，大多数伙伴）
自行确认终端场景、用户价值与目标人群
对照第 4 章选定合作模式，按开放平台文档与第三部分技术方案自助完成接入与联调
完成后提交审核，通过后灰度上线、全量发布
路径 B · 商务协作（深度合作 / 场景不匹配）
希望深度合作：联合 PR、「WorkBuddy 认证」标识、联名款、定制集成等
现有文档与自身场景不匹配，需要定制方案或能力扩展
通过开放平台提交合作意向，商务一对一评估并设计合作方案
双方各指定一名负责人（owner）对齐节奏与交付物

12.4 接入准入与审核
为保障终端用户体验与数据安全，硬件应用接入 WorkBuddy 需通过准入审核。整体要求如下，细则以开放平台官网公示为准。
准入条件
完成企业实名认证：营业执照四要素核验；已有腾讯云 / 微信公众号企业实名的，可扫码快速认证
硬件已量产，或有明确的量产计划，产品符合相关法律法规
具备基本的数据安全与用户隐私保障能力，签署《开发者服务协议》《隐私保护指引》《数据处理协议》
审核流程
在开放平台注册入驻并完成企业认证，创建硬件应用、配置能力
开放合作团队评估场景匹配度、体验与合规
测试环境联调验证后提交审核，审核通过开通正式凭证
上架与退出
联调验收通过后先灰度上线，再全量发布
体验或合规不达标的，限期整改
严重违规的，中止接入并下线相关能力
12.5 品牌使用与授权
品牌使用按合作深度分档管理。无论何种合作模式，未经 WorkBuddy 书面授权，不得在产品、包装及任何宣传物料中使用 WorkBuddy 商标与 Logo。
接入即可用 · 兼容表述
通过开放平台完成接入后，即可对外说明「兼容 WorkBuddy」「适配 WorkBuddy」
该档不包含商标授权，不得在产品及外包装上使用 WorkBuddy Logo
深度合作 · 认证标识
深度合作产品需通过专门的认证流程（流程与标准单独说明），并签署品牌授权合同
认证通过后，方可在合作产品与包装上使用「WorkBuddy 认证」标识
市场宣发 · 先评估
有 PR / 市场宣推需求的，需提前卷入 WorkBuddy 市场与公关团队评估
评估通过后，按双方确认的口径与节奏执行

13.2 数据看板与洞察
合作正式上线后，WorkBuddy 将向合作方提供专属数据看板与定期洞察报告，覆盖设备健康度、用户使用行为、商业化表现及反馈质量等维度，支撑合作方持续优化产品体验与运营策略。具体数据范围与交付形式在合作启动后由双方对齐确认。
13.3 联合宣发
联合宣发
不属于自助接入的默认权益
：涉及 WorkBuddy 品牌与 Logo 的宣发物料，需先取得品牌授权；在产品与包装上使用「WorkBuddy 认证」标识，需先通过官方认证。相关诉求请通过商务对接，由双方市场团队评估后执行（分层口径见 §4.5，品牌细则见 §12.5）。以下为联合宣发的常见方向：
发布节点
新品发布联合站台、双方渠道同步发声。
内容共创
联合场景视频、评测与用户故事等内容共建。
渠道曝光
WB 生态内专区曝光、消息触达及会员活动联动。
共同预算
关键节点联合投放，费用与效果按约定分摊。
以上方向均需双方商务与市场团队评估确认后执行，具体权益与节奏 case by case 对齐。
