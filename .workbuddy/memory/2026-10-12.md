## 分类纠错：不把「开源自托管」列为第六种形态（用户质疑后修正）
- 用户质疑上一轮把 DeepSeek Harness 单列为「开源运行时（自托管）」第六类形态。判断：用户正确，原做法是分类维度混用。
- 理由：前五类按「跑在哪、人怎么接入」划分（IDE插件/命令行/编辑器分叉/桌面工作台/云端平台）；「开源自托管」按「谁控制代码、什么许可」划分，是治理属性不是形态属性。Pi 本身是纯终端智能体（read/write/edit/bash 四工具）落在命令行类；DeepSeek Harness 官方「一切皆插件」，UI 也是插件，可跑 CLI 也可接 IDE，不是一种形态而是可多种实现的运行时。维度混用导致「自托管的云端平台」无处归类。
- 改法：P06 标题改为「两个正交维度：形态 × 控制权」；上半表恢复五类形态（命令行行首加 Pi）；下半新增「维度二 · 控制权」四张属性卡（DeepSeek Harness / Pi / OpenCode 三张 ✓自托管✓换模型 + MIT 开源；对照卡「商业闭源产品」✕自托管✕换模型 + 商业许可）；判断卡改为「它是独立的一维，不是第六种形态…Model + Harness = Agent 说的正是这一维」。
- P07 第 4 问措辞同步：由「是否必须自托管或换模型 / 开源运行时」改为「控制权要不要握在自己手里 / 叠加开源路线」，避免又把它读成一种形态。
- 通用教训（写 PPT 分类表时）：多维度属性必须正交拆分，不能因为某个产品「看起来特殊」就给它单开一类；先问「这一行的划分标准和其它行是不是同一个」。
- 代码 bug 记录：ctrl 列表第三项写成元组需整体取用，误写 attrs[2][0] 只取首字符（页面显示「M」「商」），已改 attrs[2]。

## P06 减负改版（用户反馈「有点乱」）
- 问题：上一轮改成「两个正交维度」后，页面有 45 个文本块、5 个视觉模块（维度一标签+表+维度二标签+4张属性卡+判断卡），信息过载。且副标题「别把不同维度塞进一张表」与判断卡「不是第六种形态」都是在回应读者不知道的修订历史——自我批评式文案不应出现在成品课件。

- 结果：31 文本块（24 个为表格单元格）、3 视觉模块，溢出 0。
- 设计教训：① 课件文案必须面向「没有修订历史的读者」，禁止出现回应旧版本错误的句子；② 单页视觉模块 ≤3，「维度一/维度二」这类方法论标签本身就是噪音，模块自己会长出结构。
