# 项目长期约定

## 《Coding Agent 工程实践（通用版）》PPT（讲师：杨庆刚）

- **构建**：`Coding Agent 实战指南/build_ppt2.py`，本地 python-pptx 生成，输出同目录 pptx。隔离环境按 RefactoryMem 记录的路径。
- **视角纪律（用户明确要求）**：幻灯片页面上只能有**给听众看的话**；讲师要读的内容（会话坐标、数据来源核对提醒、演示编号、备课注意事项）一律写进**备注栏**，投影不显示。
- 禁止出现在页面上的元语言：「本课判断 / 判断」（已改为「结论」）、「讲课时在这里取」「照着打开即可」「演讲前建议核对」、内部会话坐标（Zcode › 项目 › 分支 · 消息）。
- 演示角标只写「现场演示」/「现场演示 ×N」，编号不出现在页面上。
- 内部项目名（StdCommuProtocol、V3、液体处理平台）不进页面，只进备注。
- **结论卡纪律**：`judge_card(...)` / `bottom_judge(...)` 的结论必须是**本页内容的收束**，不能写成本章元判断、前置动作或另一条延伸观点——用户会立刻察觉「结论和页面不匹配」。写法模板：先一句话归纳本页主体，再接一句落点；原文若有个好观点但属于前提/延伸，降级为结论的末句而不是主体。
- **自动化四项**：页码（footer 自动编号）、目录区间（fill_toc_ranges 按页脚章节名归并）、交叉引用（@@ 页面标题 → Pxx 自动回填）、结论卡溢出自检（构建时用 PIL 按雅黑度量估算行数，超出卡片即打印 `[OVERFLOW]`）。另有 `fill_notes()` 按页面主标题匹配备注，增删页都不错位。
- **结论卡容量经验值**：`judge_card` 文本区 = w-48 × h-58、行距 1.6；`bottom_judge` = w-132 × h-16、行距 1.45。雅黑实际行高约 字号的 1.32 倍 × 行距倍数，比直觉大——写满 60 字以上就必须先量再定，别凭感觉加字。
- 第 3 章起（认知篇及之后）不得出现任何产品名；产品名只允许出现在第 1、2 章。

## 协作教训

- 用户说某章「只留第 N 页」时，指认的通常是**内容页**，章节扉页默认保留。不确定先问，别按字面全删（曾误删实战篇扉页，被追问后恢复）。
