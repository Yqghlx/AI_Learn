## 调研：github.com/wheresryan22/anatomy 能否用于培训 PPT

- 仓库性质：不是素材库，是一个**完整的 Agent Skill 包**（MIT）。让 agent 把抽象技术概念「发明成一个真实可运作的物理机械装置」，画成等距（isometric）交互插图（SVG / WebGL / 3D beta）。兼容 Claude Code、Antigravity、OpenCode、Codex。
- 结构规模：`SKILL.md` 173 行（常驻）；`references/` 8 个文件约 2400 行（按需加载）；`kit/` 约 17000 行零第三方依赖（Node 20.10+ 内置模块）；`examples/` 8 个图形，**构建好的 HTML 已提交可直接打开**；`kit/audit.mjs` + headless Chrome 截图做几何审计与自查。
- 与 PPT 的四处对齐（已给用户对图）：SKILL.md 短常驻 ↔ P21 规则层；references 按需 ↔ P23 能力层；kit+examples ↔ P22 任务层；audit+读 PNG 自查 ↔ P15 可运行验证。
- 判断：**不适合给 PPT 配图**（深空科技风 vs 等距浅色机械风冲突；PPT 只能放静态图，交互性丢失；构建需几分钟到 20 分钟）。**适合当第 5 章「技能层」的现成案例**。
- 风险：README 明确 "Written for Claude Code"，而 PPT 第 3 章起禁止产品名 → 只能用泛化表述或只进备注栏。现场演示应用 `examples/*/` 下已构建的 HTML（免构建、零风险），不要 live 跑 build.mjs。
- **用户决定：先不用**，PPT 维持 31 页现状。以上对齐关系与风险判断留档，以后若要引入「技能层案例」可直接复用本条（优先路径：只进 P23/P24/P15 备注栏，页面不提工具名）。
- 附带结论：anatomy 这类 Agent Skill 仓库本身就是「渐进式披露上下文」的好标本，将来写别的材料需要举例时可再用。

## 调研：github.com/remotion-dev/remotion 能否用于培训 PPT

- 仓库定位（README 原文）：**"Video tools for the agent era."** 三大用法首条即 "Make videos agentically: Turn your idea into a video using your coding agent"。用 React 编程做视频，本地 Studio + AWS Lambda 批量渲染。monorepo：Bun 主 + Turbo + Vitest 5 + Oxfmt，39,015 次提交。
- **关键发现：仓库自带 63 个 Agent Skills**（`.agents/skills/` 下 63 个 SKILL.md），覆盖 add-bug / add-cli-option / add-effect / deprecate-api / docs / issue-management / merge / pr-ready / release / formatting / remotion-best-practices / remotion-render / studio-config-option-lifecycle / writing-tests / video-report 等。另有 `.claude`（符号链接）、`.codex/environments`、`AGENTS.md`、`@remotion/codemods`（给 agent 改代码提速）、Agent plugin（原 Codex plugin）。
- 与 anatomy 的层级差：anatomy = **一个技能**；remotion = **一个组织把 63 个工程动作全部技能化**。正好对应 PPT 第 6 章「团队落地 / 组织级沉淀」的论点，比 anatomy 高一层。
- **许可硬约束（必须提醒）**：Remotion License，非开源协议。免费仅限：个人、≤3 人的营利组织、非营利、评估用途。超过 3 人的营利公司须买 Company License。→ 企业内训/团队使用 Remotion 出视频前必须先确认公司许可。
- 判断：**不适合做 PPT 转视频**（31 页版式要全部重写成 React 组件，工作量巨大；需 Node/Bun + Chrome + ffmpeg；且许可有商业风险）。**不适合现场演示**（演示成本远高于 anatomy 的现成 HTML）。唯一可取的仍是当案例进备注栏。
- **用户决定：不用，只看结论。** PPT 维持 31 页。留档备查：若将来第 6 章需要「组织级技能沉淀」的真实例证，优先取 remotion 的 63 个 skills；若只需要「单个技能长什么样」，取 anatomy。
- 跨两个仓库的观察（供以后写材料用）：生态正在把工程知识技能化，且层级分明——单技能（anatomy）→ 组织级技能库（remotion 63 个）→ 工具自带 agent 适配（.claude / .codex / AGENTS.md 已成新仓库标配）。写「团队落地 / 规模化」类内容时，这是现成的证据链。
