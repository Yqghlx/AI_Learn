# STORY.md — Coding Agent 实战指南（研发效能内训）

## ① 意图对齐

- **目标受众**：一线研发工程师（后端 / 前端 / 全栈），具备 1–5 年工程经验，日常用 IDE 写代码，多数人已用过补全类工具但未形成稳定工作流。场合：内部技术培训（中高密度，可讲 60–90 分钟）。
- **核心目标**：讲完后观众要**相信**三件事 ——（1）Coding Agent 不是"更快的补全"，而是"会调用工具的执行者"，心智模型必须换；（2）国内四强没有绝对的赢家，选型看生态位而非跑分；（3）决定产出质量的不是模型，而是你给它的**上下文结构**与**约束边界**。观众要**记住**三件可带走的东西：一份 AGENTS.md 骨架、一个任务简报四要素模板、一套安全护栏四件套。观众要**做**的事：本周内在自己的仓库建一个 AGENTS.md，并用一个真实小需求跑通一轮增量交付。
- **PPT 长度**：21 页。Hero 配额 5 页（01/07/12/17/21），占 24%。
- **视觉调性**：深空科技 · 高对比 · 代码质感 · IDE 夜色 · 克制理性。
- **内容边界**：
  - 必讲：范式跃迁、能力栈、国内四强对比表、选型逻辑、上下文六层、AGENTS.md、任务简报契约、增量循环、自主度分级、安全护栏、团队落地路径。
  - 不讲：模型训练原理、Transformer 架构、海外工具（Cursor / Claude Code / Copilot）单独立页（仅作为坐标系一句带过）、商业融资与股价。
  - 禁碰：绝对化的"某某最强"结论；未标注来源的精确数字；承诺 Agent 能替代人做架构决策。
